# Padlet 荒らし対策Bot & 自動復旧システム (Ultra 2.0)
【完全無料・内部API対応版 / GitHub公開リポジトリ最適化】

Padletのあらゆる荒らし行為（セクション増殖、同一投稿・同一画像連投、画像キャプションスパム、長文・URL連投、短時間DDoS攻撃、非コラボレーター投稿、不正昇格）を**0.5〜1秒単位の超高速**で検知し、自動処罰およびバックアップからの完全復旧を行う24時間稼働防衛Botです。

**有料API（api.padlet.dev）は一切不要。完全に無料の内部API（padlet.com）のみで全ての防衛・復旧機能が動作します。**
さらに、**GitHubの公開リポジトリ（Public Repo）に対応**しており、トークンやパスワードはすべてRailway側の環境変数で安全に管理・隠蔽できます。

---

## 🌟 主な機能と防衛ロジック

1. **🚫 有料API不要・完全内部API化 (無料稼働):**
   - 有料のPadlet Developer API Keyは不要。ブラウザのSession Token（Bearer）のみで、投稿取得・作成、セクション再構築、権限変更、荒らし削除の全機能が100%同一に動作します。
2. **🔔 Discord Webhook 連携時は Webhook のみで通知 (排他制御):**
   - Discord Webhook URL が設定されている場合は、**Webhookのみで通知を送信し、Padletボード上には余計な通知投稿を一切作成しません**。
   - Discord Webhook URL が空（未設定）の場合のみ、**Padletボード上の指定通知セクション（セクション荒らし時はバックアップ部屋の同名セクション）に自動投稿**して知らせます。
3. **🏷️ 投稿フィールド (custom_properties) の自動取得 & 適用:**
   - ボードにカスタム投稿フィールドがある場合、URL設定時（ボード情報解析時）に元からある既存投稿を走査し、**カスタムキーとカスタム値を自動検出・取得**。
   - 通知投稿作成時やバックアップ復元コピー時にこのフィールドを付与して投稿するため、カスタムフィールド必須のボードでも投稿が弾かれません。
4. **🌐 全体の権限（visitorRole）の強制維持 (コメンター対応):**
   - URLを知っている人の権限を「**アクセスなし (none)**」「**閲覧のみ (reader)**」「**コメンター (commenter - コメントのみ可能)**」などに固定。
   - 荒らしによって勝手に権限が引き上げられても、ミリ秒〜秒単位で即座に設定値へ強制復旧。
5. **⛔ 投稿荒らし検知と確実な処罰 (読者固定 & 投稿・コメント全削除):**
   - **① 連投爆撃**: 1秒間に2投稿以上、または2秒間に4投稿以上検知した場合、**その荒らした人のみ**を読者（reader）に処罰し、その人の全投稿および全コメントをボードから完全に一掃。
   - **② 同一画像の短期間複数連投**: 短期間に同一画像を重複投稿したユーザーを読者（reader）に処罰し、全投稿および全コメントを一掃。
   - ※通常の発言や会話を誤検知しない高精度判定アルゴリズムを搭載。
6. **🗑️ 読者にはしない安全な違反投稿削除 (投稿のみ削除):**
   - **① 画像キャプション50文字以上の投稿**: 該当投稿のみを即座に削除（ユーザーは読者にしません）。
   - **② コラボレーター以外の投稿**: 登録コラボレーター以外の投稿のみを削除（※全体の権限がライターの場合はコラボレーター外でも投稿は削除されません。また、全体の権限が何であってもコメントは常に許可されます）。
   - **③ コメント違反時のピンポイント削除**: コメントに連投等の違反があった場合は、その違反者の投稿とコメントのみを削除し、周りの投稿やコメントは一切巻き込みません。
7. **📂 セクション全削除からのバックアップ完全復元 & 正常投稿保護:**
   - セクション増殖荒らし検知時または手動復元時、メインボードの既存セクションを**必ず全部確実に削除**してから、バックアップからセクションを再構築。
   - **荒らしに検知されていない正常な投稿は絶対に削除せず保護**。
   - **荒らしではないコラボレーターの権限は絶対に下げません**。
   - バックアップボードからセクションと投稿を正確に復元し、完了後に全体の権限を設定値（コメンター等）に自動復旧。
   - Web管理画面からいつでも「**📥 バックアップ投稿同期**」や「**⚠️ 今すぐ完全復元**」が可能。
8. **👑 部屋主（オーナー）の絶対保護:**
   - 部屋主の投稿や権限はいかなる場合も安全に保護（コラボレーター未登録でも削除されません）。
9. **🔄 デュアルアカウント (2つのToken) によるレート制限(429)分散:**
   - 2個の管理アカウントトークンを交互にローテーション利用し、大量削除時でもPadlet側の429制限を回避。
10. **🔍 ダブルチェック再確認システム:**
    - 投稿削除後に再確認を行い、万が一残存があれば追撃削除。
    - セクション復旧後、バックアップとの整合性（タイトル・個数）を自動照合。
11. **🛑 安全設計: 起動時は監視オフ（手動オン）:**
    - サーバー起動直後は安全のため監視は停止状態で立ち上がります。管理画面でURLや権限設定を確認後、「監視開始」ボタンを押すことで安全に防衛を開始できます。

## 🚂 Railway での起動方法・デプロイ手順 (完全ガイド)

### ステップ 1: GitHub にコードをプッシュ
このフォルダの全ファイルをGitHubの新しいリポジトリ（Public / Privateどちらでも可）にプッシュします。

### ステップ 2: Railway プロジェクト作成
1. [Railway](https://railway.app/) にログインし、「**New Project**」をクリック。
2. 「**Deploy from GitHub repo**」を選択し、先ほどプッシュしたリポジトリを選択。

### ステップ 3: Railway の環境変数 (Variables) を設定
リポジトリのデプロイが始まったら、プロジェクトの「**Variables**」タブを開き、以下の環境変数を追加します：

| 環境変数名 (Variable Name) | 必須 | 説明 | 設定例 |
| :--- | :---: | :--- | :--- |
| `ADMIN_PASSWORD` | **推奨** | **Web管理画面のログインパスワード (環境変数で設定)**<br>※未設定時は起動時に安全なランダムパスワードが自動生成されログに出力されます。不特定多数への公開に備え、必ず設定してください。 | `MySecretPass2026!` |
| `PADLET_SESSION_TOKEN` | **必須** | **Padlet Web Session Token 1 (メイン管理アカウント)**<br>ブラウザのデベロッパーツール等から取得したBearerトークン。 | `eyJhbGciOiJIUzI1Ni...` |
| `PADLET_SECONDARY_TOKEN` | 任意 | Padlet Web Session Token 2 (サブ管理アカウント・429回避用) | `eyJhbGciOiJIUzI1Ni...` |
| `DISCORD_WEBHOOK_URL` | 任意 | Discord通知用 Webhook URL<br>※**未設定の場合はPadletボード内の指定セクションに自動通知**されます。 | `https://discord.com/api/webhooks/...` |
| `SECRET_KEY` | 任意 | Flaskセッション暗号化キー (未設定でも各デプロイごとに暗号学的ランダム値が自動生成され、他人のデプロイと被りません) | `任意のランダム文字列` |
| `PORT` | - | 自動注入されるため手動設定不要 | `8080` |

### ステップ 4: 公開URLの発行と管理画面へのアクセス
1. Railwayの「**Settings**」タブを開きます。
2. 「**Networking**」セクションの「**Generate Domain**」をクリック。
3. 発行されたURL（例: `https://xxxx.up.railway.app`）をブラウザで開きます。
4. ステップ3で設定した `ADMIN_PASSWORD` を入力してログイン。
5. **メインボードURL** を入力して「取得」を押すと、**セクション一覧と投稿フィールド(custom_properties)が自動検出**されます。
6. Webhook未指定の場合は「通知先セクション」を選択（または「➕ 自動作成」をクリック）。
7. **バックアップボードURL** を入力して「取得」を押し、「監視開始」をクリックすれば24時間防衛が始まります！

## 💻 Local (自分のPC) での起動方法

1. **ライブラリのインストール:**
   ```bash
   pip install -r requirements.txt
   ```
2. **`.env` ファイルの作成:**
   `.env.example` をコピーして `.env` という名前にリネームし、トークンやパスワードを記入します。
3. **起動:**
   ```bash
   python app.py
   ```
4. ブラウザで `http://localhost:8080` を開き、管理パネルにアクセスします。
