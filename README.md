# Padlet 荒らし対策Bot & 自動復旧システム (Ultra 2.0)

Padletのあらゆる荒らし行為（セクション増殖、同一投稿・同一画像連投、画像キャプションスパム、長文・URL連投、短時間DDoS攻撃、非コラボレーター投稿、不正昇格）を**0.5〜1秒単位の超高速**で検知し、自動処罰およびバックアップからの完全復旧を行う24時間稼働防衛Botです。

**GitHubの公開リポジトリ（Public Repo）に対応**しており、トークンやパスワードはすべてRailway側の環境変数で安全に管理・隠蔽できます。

---

## 🌟 主な機能と防衛ロジック

1. **🌐 全体の権限（visitorRole）の強制維持:**
   - URLを知っている人の権限を「**アクセスなし (none)**」「**閲覧のみ (reader)**」などに固定。
   - 荒らしによって勝手に権限が引き上げられても、ミリ秒〜秒単位で即座に設定値へ強制復旧。
2. **👥 20人同時荒らし・分散DDoSへの並列一括処罰 (読者固定):**
   - 荒らしアカウントは**コラボレーターから削除（追放）するのではなく、確実に「読者 (reader)」として設定・固定**し、これ以上の書き込みを物理的に封殺します。
   - `ThreadPoolExecutor` により、20アカウント同時の荒らしや短時間大量連投が発生しても、**0.5秒以内に全員の権限を「読者」に降格し、全投稿を一斉並列削除**。
   - 複数アカウントによる同一本文（10文字以上）や同一画像爆撃（組織的コピペ荒らし）も自動検知して一網打尽。
3. **📂 セクション＋投稿の完全自動復元 & 手動同期:**
   - セクション増殖荒らし検知時、直ちに全体権限をロックダウンし、汚染セクションを初期化。
   - バックアップボードから**セクションを再構築し、すべての投稿を対応セクションへ並列コピー**して完全復元。
   - Web管理画面からいつでも「**📥 バックアップ投稿同期**」ボタンで手動コピー・同期が可能。
4. **🖼️ 画像キャプション50文字制限 (スパム対策):**
   - 画像のキャプション欄に大量の文字を貼り付ける荒らし投稿を検知。50文字を超えた瞬間に**該当投稿を即時削除＆アカウント制裁**。
5. **👑 部屋主（オーナー）の絶対保護:**
   - 部屋主の投稿や権限はいかなる場合も安全に保護（コラボレーター未登録でも削除されません）。
6. **🔄 デュアルアカウント (2つのToken) によるレート制限(429)分散:**
   - 2個の管理アカウントトークンを交互にローテーション利用し、大量削除時でもPadlet側の429制限を回避。
7. **🔍 ダブルチェック再確認システム:**
   - 投稿削除後に再確認を行い、万が一残存があれば追撃削除。
   - セクション復旧後、バックアップとの整合性（タイトル・個数）を自動照合。
8. **📢 Discord Webhook 強化通知 (@everyone メンション対応):**
   - 荒らし検知・一括処罰・復元完了時に `@everyone` メンション付きで詳細な埋め込みレポートを即時配信。

## 📁 GitHub に置くファイル構成 (すべて公開OK)

このリポジトリには機密情報（パスワードやAPIキー）は一切含まれていません。そのままGitHubの公開リポジトリへプッシュできます。

```text
padlet-anti-spam-bot/
├── app.py                  # メインWebサーバー & API (Flask)
├── padlet_client.py        # Padlet APIクライアント (レート制御 & 2アカウント分散)
├── monitor_engine.py       # 高速監視・DDoS検知・自動防衛・復旧エンジン
├── templates/
│   └── index.html          # Web管理ダッシュボードパネル (HTML/CSS/JS)
├── Procfile                # Railway用プロセス定義 (web: python app.py)
├── requirements.txt        # 依存ライブラリ一覧
├── .gitignore              # .env やローカル設定をGitから完全除外
├── .env.example            # 環境変数のサンプルテンプレート
└── README.md               # 説明書 (本ファイル)
```

> **注意:** `.env` および `bot_config.json` は `.gitignore` によって除外されているため、GitHubに公開されることはありません。

## 🚂 Railway での起動方法・デプロイ手順 (完全ガイド)

### ステップ 1: GitHub にコードをプッシュ
このフォルダの全ファイルをGitHubの新しいリポジトリ（Public / Privateどちらでも可）にプッシュします。

### ステップ 2: Railway プロジェクト作成
1. [Railway](https://railway.app/) にログインし、「**New Project**」をクリック。
2. 「**Deploy from GitHub repo**」を選択し、先ほどプッシュしたリポジトリを選択。

### ステップ 3: Railway の環境変数 (Variables) を設定
リポジトリのデプロイが始まったら、プロジェクトの「**Variables**」タブを開き、以下の環境変数を追加します：

| 環境変数名 (Variable Name) | 必須 | 説明 | 設定例 |
| :--- | :---: | :--- | :--- |
| `ADMIN_PASSWORD` | **推奨** | **Web管理画面のログインパスワード (環境変数で設定)**<br>※未設定時は起動時に安全なランダムパスワードが自動生成されログに出力されます。不特定多数への公開に備え、必ず設定してください。 | `MySecretPass2026!` |
| `PADLET_API_KEY` | ◯ | Padlet公式API Key (Developer画面で発行) | `pl_api_abcdef123456...` |
| `PADLET_SESSION_TOKEN` | ◯ | Padlet Web Session Token 1 (メイン管理アカウント) | `eyJhbGciOiJIUzI1Ni...` |
| `PADLET_SECONDARY_TOKEN` | 任意 | Padlet Web Session Token 2 (サブ管理アカウント・429回避用) | `eyJhbGciOiJIUzI1Ni...` |
| `DISCORD_WEBHOOK_URL` | ◯ | Discord通知用 Webhook URL | `https://discord.com/api/webhooks/...` |
| `SECRET_KEY` | 任意 | Flaskセッション暗号化キー (未設定でも各デプロイごとに暗号学的ランダム値が自動生成され、他人のデプロイと被りません) | `任意のランダム文字列` |
| `PORT` | - | 自動注入されるため手動設定不要 | `8080` |

### ステップ 4: 公開URLの発行と管理画面へのアクセス
1. Railwayの「**Settings**」タブを開きます。
2. 「**Networking**」セクションの「**Generate Domain**」をクリック。
3. 発行されたURL（例: `https://xxxx.up.railway.app`）をブラウザで開きます。
4. ステップ3で設定した `ADMIN_PASSWORD` を入力してログイン。
5. **メインボードURL** と **バックアップボードURL** を入力して「取得」を押し、「監視開始」をクリックすれば24時間防衛が始まります！

## 💻 Local (自分のPC) での起動方法

1. **ライブラリのインストール:**
   ```bash
   pip install -r requirements.txt
   ```
2. **`.env` ファイルの作成:**
   `.env.example` をコピーして `.env` という名前にリネームし、トークンやパスワードを記入します。
3. **起動:**
   ```bash
   python app.py
   ```
4. ブラウザで `http://localhost:8080` にアクセスし、ログインします。
